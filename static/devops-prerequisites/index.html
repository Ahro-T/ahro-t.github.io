01. 강의 소개

영상 구간: 00:00부터 보기

학습 목표

  • DevOps 입문 전에 필요한 기술 범위를 설명한다.
  • Linux·가상화·네트워크·YAML이 이후 도구와 어떻게 연결되는지 이해한다.

핵심 개념

DevOps는 특정 제품 하나가 아니라 개발과 운영의 전달 과정을 자동화하고 반복 가능하게 만드는 실천 방식입니다. Docker나 Kubernetes를 먼저 외우기보다 운영체제, 네트워크, 구성 파일의 기본 모델을 알아야 장애 상황에서 원인을 추적할 수 있습니다.

실습

uname -a
whoami
pwd

현재 운영체제, 사용자, 작업 디렉터리를 기록합니다.

확인 질문

왜 Linux와 네트워크를 먼저 배우나요?

대부분의 서버 도구가 Linux 프로세스와 네트워크 위에서 동작하기 때문에, 상위 도구의 오류를 하위 계층에서 진단하려면 기본 모델이 필요합니다.

02. Linux CLI

영상: Linux 구간 보기

핵심 개념

셸은 명령을 해석해 운영체제에 전달합니다. 경로는 절대 경로와 상대 경로로 구분하며, 명령은 현재 작업 디렉터리와 권한의 영향을 받습니다.

기본 명령

pwd
ls -la
cd /tmp
mkdir devops-lab
cd devops-lab
touch notes.txt
cp notes.txt notes-copy.txt
mv notes-copy.txt archive.txt
rm archive.txt

파일 읽기와 검색

cat /etc/os-release
head -n 5 /etc/passwd
tail -n 20 /var/log/syslog
grep -i "error" application.log
find . -name "*.yaml"
주의
rm은 휴지통을 거치지 않습니다. 경로와 와일드카드를 실행 전에 확인하세요.

과제

~/devops-lab에 폴더 세 개와 텍스트 파일을 만들고, 상대 경로만 사용해 복사·이동·삭제해 보세요.

03. 패키지·서비스·VI

영상: 패키지 구간 보기

패키지 관리자

패키지 관리자는 저장소에서 소프트웨어와 의존성을 설치하고 업데이트합니다. 배포판마다 도구가 다릅니다.

# Debian/Ubuntu
sudo apt update
sudo apt install nginx

# RHEL 계열
sudo yum install nginx

서비스 관리

sudo systemctl status nginx
sudo systemctl start nginx
sudo systemctl enable nginx
journalctl -u nginx --since today

VI 최소 사용법

  • i: 입력 모드
  • Esc: 명령 모드
  • :w: 저장
  • :q: 종료
  • :wq: 저장 후 종료
  • :q!: 변경 폐기

오류 점검 순서

  1. 서비스 상태
  2. 최근 로그
  3. 설정 문법
  4. 포트 점유
  5. 파일 권한

04. VirtualBox 설치

영상: VirtualBox 구간 보기

가상화 모델

하이퍼바이저는 물리 컴퓨터의 CPU·메모리·디스크·네트워크 자원을 여러 가상 머신에 나눠 제공합니다. 각 VM은 자체 운영체제와 커널을 가집니다.

VM 생성 체크리스트

  • 호스트 CPU 가상화 기능 활성화
  • 충분한 메모리와 디스크 확보
  • 운영체제 ISO 선택
  • 부팅 순서와 네트워크 어댑터 확인
  • 설치 후 Guest Additions 필요 여부 확인
흔한 문제
64비트 게스트가 표시되지 않거나 VM이 시작되지 않으면 BIOS/UEFI 가상화 설정과 다른 하이퍼바이저 충돌을 점검합니다.

05. VM 연결과 SSH

영상: 연결 구간 보기

SSH의 역할

SSH는 암호화된 원격 셸을 제공합니다. 접속에는 대상 IP, 사용자, 인증 방식, SSH 서버 상태, 네트워크 경로가 모두 필요합니다.

ip addr
ip route
ss -lntp | grep :22
ssh user@192.168.56.10
ssh -i ~/.ssh/id_ed25519 user@192.168.56.10

접속 실패 진단

  1. VM이 실행 중인가?
  2. IP 주소가 맞는가?
  3. 호스트에서 대상 IP에 도달 가능한가?
  4. 22번 포트가 열려 있는가?
  5. 사용자와 키 권한이 올바른가?
ping -c 3 192.168.56.10
nc -vz 192.168.56.10 22
ssh -vvv user@192.168.56.10

06. VirtualBox 네트워킹

영상: 네트워크 구간 보기

어댑터 모드

모드특징용도
NAT게스트가 외부로 나가기 쉬움일반 인터넷 접근
Bridged게스트가 실제 LAN의 장치처럼 동작다른 장치에서 직접 접근
Host-only호스트와 게스트 전용 네트워크격리된 실습

권장 실습

어댑터 1은 NAT, 어댑터 2는 Host-only로 구성하면 인터넷 접근과 호스트-게스트 SSH를 동시에 실습하기 쉽습니다.

ip addr
ip route
ping -c 3 8.8.8.8
getent hosts example.com

07. Vagrant

영상: Vagrant 구간 보기

왜 필요한가

GUI로 VM을 수동 생성하면 설정이 사람의 기억에 남습니다. Vagrantfile은 베이스 이미지, 자원, 네트워크와 프로비저닝을 코드로 기록해 같은 환경을 다시 만들 수 있게 합니다.

기본 흐름

mkdir vagrant-lab && cd vagrant-lab
vagrant init ubuntu/jammy64
vagrant up
vagrant status
vagrant ssh
vagrant halt
vagrant destroy -f

Vagrantfile 예시

Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"
  config.vm.network "private_network", ip: "192.168.56.20"
  config.vm.provider "virtualbox" do |vb|
    vb.memory = 2048
    vb.cpus = 2
  end
end
버전 주의
Box 이름과 VirtualBox 호환성은 시점에 따라 달라질 수 있습니다. 오류가 나면 공식 Vagrant Cloud의 현재 box 정보를 확인하세요.

08. DNS

영상: DNS 구간 보기

이름 해석 과정

애플리케이션은 도메인 이름을 IP 주소로 바꾼 뒤 네트워크 연결을 시작합니다. 로컬 hosts 파일, 캐시, 재귀 DNS 서버, 권한 서버가 이 과정에 관여할 수 있습니다.

cat /etc/hosts
cat /etc/resolv.conf
getent hosts example.com
nslookup example.com
dig example.com A

주요 레코드

  • A: 이름 → IPv4
  • AAAA: 이름 → IPv6
  • CNAME: 별칭 → 정식 이름
  • MX: 메일 서버
  • TXT: 검증·정책 텍스트

오해

DNS 조회 성공은 서비스가 정상이라는 뜻이 아닙니다. 이름 해석 후에도 라우팅, 방화벽, 포트, 애플리케이션 상태를 별도로 확인해야 합니다.

09. 스위칭과 라우팅

영상: 라우팅 구간 보기

같은 네트워크와 다른 네트워크

같은 서브넷의 장치는 링크 계층에서 직접 통신합니다. 다른 서브넷으로 가는 패킷은 라우팅 테이블이 선택한 게이트웨이로 전달됩니다.

ip link
ip addr
ip route
ip neigh
traceroute example.com

라우팅 테이블 읽기

default via 192.168.1.1 dev eth0
192.168.1.0/24 dev eth0 proto kernel scope link

첫 줄은 더 구체적인 경로가 없을 때 사용하는 기본 게이트웨이입니다. 둘째 줄은 로컬 인터페이스에 직접 연결된 네트워크입니다.

진단 질문

  1. 목적지와 같은 서브넷인가?
  2. 어떤 인터페이스와 게이트웨이가 선택되는가?
  3. 게이트웨이의 MAC 주소를 해석했는가?
  4. 중간 라우터나 방화벽이 패킷을 허용하는가?

10. IP 주소와 포트

영상: IP와 포트 구간 보기

주소와 프로세스

IP 주소는 네트워크 인터페이스를 식별하고, 포트는 호스트 안에서 통신 대상 프로세스를 구분합니다. 서버가 포트에서 대기해야 클라이언트가 연결할 수 있습니다.

ss -lntp
ss -lunp
curl -v http://127.0.0.1:8080
nc -vz 127.0.0.1 8080

바인딩 주소

  • 127.0.0.1: 같은 호스트에서만 접근
  • 0.0.0.0: 모든 IPv4 인터페이스에서 대기
  • 특정 IP: 해당 인터페이스에서만 대기
보안
모든 인터페이스에 바인딩하는 것은 접근 가능 범위를 넓힙니다. 방화벽과 인증을 함께 고려해야 합니다.

11. YAML과 정리

영상: YAML 구간 보기

기본 자료형

name: web
replicas: 3
enabled: true
ports:
  - 80
  - 443
metadata:
  owner: platform-team
  environment: dev

문법 규칙

  • 들여쓰기는 구조이며 탭 대신 공백을 사용합니다.
  • key: value는 매핑입니다.
  • - item은 목록입니다.
  • 문자열처럼 보이는 숫자·날짜·불리언은 따옴표가 필요할 수 있습니다.
  • 같은 레벨의 들여쓰기는 반드시 일치해야 합니다.

검증 예제

python -c "import yaml; print(yaml.safe_load(open('sample.yaml')))"
